**Sources:** keka.com/payroll-software, keka.com/hr-software, plus Keka's linked module pages (payroll processing, payroll compliance, expense management, loans & advances, employee profiles, documents, onboarding, HRIS) and Keka's public help/docs centre.

**Read this first:**
- The two main product pages are marketing overviews. Most of the granular functionality lives on the sub-module pages and in Keka's help centre, so items below are grouped by capability area rather than by webpage.
- Keka packages features into subscription tiers (broadly Foundation / Strength / Growth, plus add-ons). **Not every item here is available on every plan** — verify against the pricing page or with sales before relying on any specific item.
- Keka runs separate India (`keka.com`) and US (`keka.com/us`) products. Parts 1–2 are India-first; **Part 3 covers US salary compliance separately**.
- **Part 4 (currency) is partly a requirement spec, not a confirmed Keka feature** — read the warning at the top of that part before using it.
- Feature sets change; this reflects what was publicly documented as of August 2026.

| 31.6 | Per-legal-entity and per-location setup, which is the natural anchor for a base currency |
| 31.7 | Separate India and US products, each with its own native currency and statutory model |
| 31.8 | GCC-region payroll support (gratuity, social insurance), implying additional currency contexts |

**Gap:** there is no publicly documented feature for displaying salary/payroll figures in a *secondary* currency alongside the base currency, nor an admin-set org-wide display default with a per-user override. That is what Section 32 specifies.

## 32. Secondary currency display — requirement specification

### 32.1 Core concept

| # | Requirement |
|---|---|
| 32.1.1 | Every legal entity has a **base currency** — immutable after first payroll run, since all stored amounts, statutory calculations and filings are denominated in it |
| 32.1.2 | An admin can enable one or more **secondary (display) currencies** at the organisation level |
| 32.1.3 | Secondary currency is **display-only** — it never changes stored values, never affects tax, statutory or bank-file computation |
| 32.1.4 | The admin sets which currency is the **default displayed currency** for everyone |
| 32.1.5 | Individual users can override the org default and choose their own display currency from the permitted list |
| 32.1.6 | Admin can decide whether user-level override is allowed at all (lock vs. allow) |

### 32.2 Admin-side controls

| # | Requirement |
|---|---|
| 32.2.1 | Setting to enable/disable the secondary currency feature org-wide |
| 32.2.2 | Currency master list — add, activate, deactivate available currencies |
| 32.2.3 | Base currency declared per legal entity |
| 32.2.4 | Selection of which currencies are permitted as display options |
| 32.2.5 | Org default display currency selector |
| 32.2.6 | Scoping of the default by legal entity, location, department, pay group or employee group (an India entity may default to INR while a US entity defaults to USD) |
| 32.2.7 | Toggle: "Allow employees to change their display currency" (yes / no) |
| 32.2.8 | Restriction of the user-selectable list to a subset of enabled currencies |
| 32.2.9 | Exchange-rate source configuration — manual entry, scheduled feed, or third-party rate provider |
| 32.2.10 | Rate type selection — live/spot, monthly fixed, payroll-period-locked, or year-fixed |
| 32.2.11 | Manual rate override with effective-from date |
| 32.2.12 | Rate history retained and auditable |
| 32.2.13 | Rounding and decimal-precision rules per currency (INR 2dp, JPY 0dp, etc.) |
| 32.2.14 | Control over which surfaces show the secondary currency — payslip, salary breakup, expense claims, loans, reports, dashboards |
| 32.2.15 | Toggle for dual display (both currencies shown) vs. single display (converted only) |
| 32.2.16 | Mandatory disclaimer text on converted figures, configurable |
| 32.2.17 | Ability to bulk-reset all users back to the org default |
| 32.2.18 | Audit log entry whenever the org default or rate configuration changes |

### 32.3 User-side controls

| # | Requirement |
|---|---|
| 32.3.1 | Display-currency preference in the user's personal settings |
| 32.3.2 | Preference options limited to the admin-permitted list |
| 32.3.3 | "Use organisation default" as an explicit selectable option |
| 32.3.4 | Preference persists across web and mobile sessions |
| 32.3.5 | Preference is per-user, not per-device |
| 32.3.6 | Preference visible on the surfaces it affects, with the base amount available on hover/expand |
| 32.3.7 | Preference greyed out with an explanatory message when the admin has locked it |
| 32.3.8 | Reset-to-default action |

### 32.4 Precedence & resolution order

Resolve the displayed currency in this order, first match wins:

1. User's explicit personal preference — *if* admin has allowed overrides
2. Group-scoped default (legal entity / location / department / pay group)
3. Organisation-wide default display currency
4. Legal entity base currency (always the final fallback)

### 32.5 Scope rules — where conversion must and must not apply

| Surface | Behaviour |
|---|---|
| Payslip (statutory document) | **Base currency only** by default; converted figures permitted only as a clearly-labelled supplementary annexure, never replacing the statutory value |
| Statutory forms (Form 16, 24Q, ECR, W-2, 941) | **Base currency only** — never converted |
| Bank transfer / disbursement file | **Base currency only** — never converted |
| Salary breakup / CTC view | Dual display allowed |
| Compensation planning & budgeting | Dual display; conversion useful for cross-entity comparison |
| Payroll cost analytics & dashboards | Converted display allowed, with a common reporting currency for consolidation |
| Expense claims | Claim currency, base currency and display currency all potentially distinct — show all three |
| Loans & advances | Base currency for EMI schedule; converted as supplementary |
| Exported reports (Excel/CSV) | Include both base and converted columns plus the rate used |

### 32.6 Edge cases to handle

| # | Case |
|---|---|
| 32.6.1 | Employee transfers between legal entities with different base currencies mid-year |
| 32.6.2 | Historical payslips — must render at the rate effective for that period, not today's rate |
| 32.6.3 | Rate unavailable for a date — defined fallback (last known rate, flagged as stale) |
| 32.6.4 | Rounding drift when converted component values are summed — always convert the total, then display components, not the reverse |
| 32.6.5 | Currency with different decimal precision than the base |
| 32.6.6 | Arrears spanning periods with different rates |
| 32.6.7 | Admin changes the org default mid-cycle — users on default see the change; users with overrides do not |
| 32.6.8 | Admin disables a currency that some users have selected — those users fall back to the org default with a notification |
| 32.6.9 | Contractors or expats paid in a currency other than the entity base |
| 32.6.10 | Every converted figure carries a visible label showing the rate and rate date |
